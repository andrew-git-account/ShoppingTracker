# Data Schema — Shopping Tracker

Defines the data contracts for storage and LLM communication.

---

## Receipt Storage (SQLite, `data/shopping_tracker.db`)

Receipts moved from a JSON file to SQLite in SP-034 — one row per receipt in `receipts`, one row per line item in `receipt_items` (SQL rows have no inherent order, so `position` reconstructs the original item order on read-back). `subtotal` is never stored; it's computed on the fly from items every time a receipt is loaded. `shopping_tracker.db` is a single file that later migrations (SP-035/SP-036) add their own tables to alongside these two.

```sql
CREATE TABLE receipts (
    id TEXT PRIMARY KEY,
    store_name TEXT,
    purchase_date TEXT,
    tax_amount REAL NOT NULL DEFAULT 0,
    discount_amount REAL NOT NULL DEFAULT 0,
    total_amount REAL,
    saved_at TEXT NOT NULL,
    currency TEXT NOT NULL DEFAULT 'USD',
    user_email TEXT NOT NULL,
    is_deleted INTEGER NOT NULL DEFAULT 0,
    linked_transaction_id TEXT
);
CREATE TABLE receipt_items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    receipt_id TEXT NOT NULL REFERENCES receipts(id),
    name TEXT NOT NULL,
    price REAL NOT NULL,
    quantity INTEGER NOT NULL DEFAULT 1,
    category TEXT NOT NULL DEFAULT 'Other',
    amount REAL NOT NULL DEFAULT 1.0,
    unit TEXT NOT NULL DEFAULT 'piece',
    position INTEGER NOT NULL
);
```

### Field reference

| Field | Type | Required | Notes |
|---|---|---|---|
| `id` | string (UUID) | Yes | Generated by the system on save |
| `saved_at` | string (ISO 8601 datetime) | Yes | When the receipt was processed |
| `store_name` | string | No | Extracted by LLM; empty string if unknown |
| `purchase_date` | string (YYYY-MM-DD) | No | Extracted by LLM; empty string if unknown |
| `currency` | string (ISO 4217) | Yes | Defaults to `"USD"` if LLM cannot determine |
| `user_email` | string | Yes | Owner of the receipt (SP-005) |
| `items[].name` | string | Yes | Product name |
| `items[].price` | number | Yes | Price per unit |
| `items[].quantity` | integer | Yes | Minimum 1; weight-based items round up to 1 |
| `items[].category` | string | Yes | Must be from the predefined category list; defaults to `"Other"` |
| `items[].amount` / `items[].unit` | number / string | Yes | Purchased amount in its representative unit (`"kg"` or `"piece"`, SP-013) |
| `items[].position` | integer | Yes | Preserves item display order on read-back — storage detail only, never exposed outside `SqliteDatabase` |
| `tax_amount` | number | Yes | Tax applied; 0.0 if none |
| `discount_amount` | number | Yes | Discount applied; 0.0 if none |
| `total_amount` | number | Yes | Final amount paid |
| `is_deleted` | boolean | Yes | `false` by default; set to `true` on soft delete |
| `linked_transaction_id` | string (UUID) or `null` | No | Statement transaction this receipt settles (SP-026/SP-037); `null` if unlinked. A receipt links to at most one transaction, but several receipts may share the same `linked_transaction_id` (SP-038) |

## LLM Response Contract

The LLM extraction prompt expects a JSON response in this shape:

```json
{
  "store_name": "Walmart",
  "purchase_date": "2026-05-07",
  "currency": "USD",
  "items": [
    {
      "name": "Milk",
      "price": 3.99,
      "quantity": 1,
      "category": "Food & Groceries"
    }
  ],
  "tax_amount": 0.32,
  "discount_amount": 0.00,
  "total_amount": 4.31
}
```

### Validation rules applied to the LLM response

| Field | Rule |
|---|---|
| `currency` | Must be uppercase ISO 4217; defaults to `"USD"` if missing or unrecognized |
| `items[].quantity` | Parsed as `max(1, int(float(value)))`; fractional quantities (weight-based items) round up to 1 |
| `items[].category` | Must match a name in the predefined category list; defaults to `"Other"` if missing or unrecognized |
| All numeric fields | Treated as 0.0 if missing |
| `store_name`, `purchase_date` | Stored as empty string if missing |
